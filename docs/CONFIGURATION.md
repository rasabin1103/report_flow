# Configuration schema 1.0
The full, machine-readable schema is at `/api/v1/report-config-schema`. Working complete examples are under `examples/*_config.json`. All objects forbid unknown keys. IDs must be unique across KPI/chart/table components; selected source columns and sections must be unique.

`report` controls title, subtitle, author, `en`/`es`, A4/LETTER, portrait/landscape, executive/detailed template, cover, summary and optional contents. `cover_style` defaults to `compact`: a branded title panel shares the opening page with the brief, KPIs and evidence. Set `full` for a separate cover. `sections` controls order and inclusion: cover, executive_summary, kpis, charts, tables, methodology. Cover and summary flags additionally gate those sections.

`dataset` controls sheet_name, encoding, delimiter, columns and missing_policy. With no column definitions, all source columns are available. Otherwise only `include:true` columns are available to filtering, metrics, tables and charts. Excluded columns cannot leak into output. A column has source, optional presentation label, optional string/number/integer/date/boolean type, and include. Explicit conversions fail if any non-null value is incompatible. Source names remain the keys in expressions; labels only affect presentation.

Automatic inference recognizes true/false booleans, numeric columns and unambiguous ISO dates (YYYY-MM-DD and ISO timestamps). Ambiguous regional date strings remain text unless an explicit date type is supplied. Explicit date conversion uses Pandas mixed parsing, with month-first behavior for ambiguous inputs; prefer ISO input. Timestamps normalize to UTC; rendered dates use YYYY-MM-DD in English and DD/MM/YYYY in Spanish. Numbers use language-specific separators. Time groups use calendar day/month/quarter/year and Monday-start weeks (periods ending Sunday). Date chart order is chronological.

Filters combine with AND. Supported operators: equals, not_equals, greater_than, greater_or_equal, less_than, less_or_equal, in, not_in, contains, is_null, is_not_null, between. Ordered comparisons and between require numbers or dates; contains requires text and uses literal substring matching. Membership takes up to 1,000 scalar values, between two ordered inclusive bounds. Nulls match only explicit null predicates, including for negative comparisons. Empty and missing numeric inputs never silently become zero.

Metrics use count_rows, count_non_null, sum, average, minimum, maximum, distinct_count. All except count_rows require a column. sum/average require numbers, minimum/maximum numbers or dates. Null values are excluded from numeric calculations; all-null numeric metrics remain null. Distinct counts exclude nulls. KPIs additionally have label, optional unit, local filters and optional numeric comparison (absolute delta from baseline, no inferred business meaning).

Charts require id, title, type, group_by, optional aggregation, metric column and presentation `unit` (for example EUR). group_by is one name or up to four names. Types: bar, horizontal_bar, line, pie, donut. time_granularity: day/week/month/quarter/year, requiring one date group. sort: ascending/descending (by metric except chronological time charts). limit: 1-40, default 15; category omissions are explicitly stated. Readability caps further restrict pies/donuts to 8, horizontal bars to 15 and other charts to 12 categories. Time charts show the latest configured intervals. Long chart labels are wrapped and shortened with an ellipsis. Use small category counts for pies and long labels. Pie/donut inputs must be nonnegative; zero totals and empty results produce an explanatory placeholder.

Tables require id/title/columns and max_rows (1-2000; default 100; maximum 12 columns). Raw tables preserve nulls as `-`. Grouped tables additionally specify group_by, aggregation, column and sort; their displayed columns must be group source names and/or `value` (the aggregate). Source name `value` is reserved in grouped tables. Omitted row counts are printed. All table headers repeat on new pages; long text wraps.

missing_policy is `unknown` (include null groups as Unknown) or `exclude` (drop null groups). Raw tables always preserve nulls. Charts never replace null metric values with zero. Chart annotations disclose omitted categories and null metric handling.

Branding: company_name, #RRGGBB primary_color/accent_color, footer_text and optional logo_base64. Supply raw base64 PNG/JPEG bytes, not a data URI, URL or path. Maximum 500 KB decoded and dimensions 1-2000 px per axis. The decoder validates content, applies JPEG orientation and re-encodes pixels without metadata, preserving PNG alpha transparency. Layout scales logos to fit without changing aspect ratio. Matplotlib ships the freely licensed DejaVu Sans fonts used and embedded by this engine; their licenses remain in the installed Matplotlib distribution. No proprietary fonts are bundled.

English/Spanish prose, chart annotations, filter descriptions, methodology, omissions, booleans and number/date formatting are localized. User-supplied labels and source cell values retain their original text. Font coverage targets Latin text; arbitrary scripts and bidirectional layout are outside this MVP.

## Editorial reporting
The opening brief includes up to two descriptive observations derived from configured chart groupings, a selected-cell coverage indicator when data is missing, and the observed date range. Shares use the complete grouped dataset before display limits and are only calculated for additive, nonnegative metrics with no null group aggregates. Distinct counts and averages do not receive misleading shares. Ties are identified. Temporal changes compare first/last available interval values with a nonzero baseline and disclose that intervals may be incomplete. They are not forecasts or proof of causal relationships.

Tables appear under a distinct data appendix, which can share a page with the end of the analysis when space permits. Small tables stay together with their headings and omission notes; longer tables paginate with repeated headers. The supplied examples use complete grouped summaries instead of the first twelve raw rows; all KPIs/charts use the full filtered scope. Raw detail tables remain configurable.

See `docs/PDF_DESIGN.md` for the visual system and acceptance checks.

## Cover identity and convenient overrides
report.title is the report/cover title; blank or whitespace-only values are invalid (maximum 200 characters). subtitle is limited to 300 characters; author to 160. Optional prepared_for (160), reporting_period (80), document_reference (80), and confidentiality (100) appear in the cover and methodology. Standalone covers use a measured title block, an undistorted logo and a documentary metadata grid. Compact covers retain the opening-page brief. Every page includes final X-of-Y pagination and data tables have localized numbered captions.

CLI generate/validate support --title, --subtitle, --logo and --cover-style. The two HTTP report endpoints accept equivalent presentation form fields and an optional logo file upload. Explicit overrides take precedence over JSON values and pass through the same schema and logo validator. See BRANDING.md.

## Additive table totals
Grouped tables can set include_total:true when their aggregation is count_rows, count_non_null or sum. The display must include value and start with a group column. The footer totals the complete grouped result, including groups omitted by max_rows, and explicitly discloses that scope if any groups are omitted. All-null sums remain missing. Averages, distinct counts, minima and maxima cannot be summed into a misleading total. Missing-category policy applies before the footer is calculated.

Narrative findings selected for the executive brief are not repeated under their charts. If the brief is disabled, chart findings remain visible. Non-selected findings still accompany their own charts.
